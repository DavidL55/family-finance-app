## 0. קרא את זה לפני שאתה מתחיל

### 0.1 מה אין לך, ומה זה מונע

**אין במערכת אף מפתח API של ספק AI אמיתי.** אין קובץ `functions/.env.local`, ואין מפתח בשום מקום אחר.

זה לא פרט טכני שולי — הוא קובע ישירות מה תוכל לראות היום. אימתתי את זה בהרצה חיה מול האמולטור ב-18.8: הקריאה `listAiModels` החזירה **מודל אחד בלבד**:

```
{"models":[{"providerId":"mock","modelId":"mock-standard","label":"מודל דמה (ללא מפתח)", ...}]}
```

כלומר: בורר המודלים בממשק יציג היום **אופציה אחת**.

| התרחיש | עובד היום בלי מפתח? | מה משתנה כשיהיה מפתח אמיתי |
|---|---|---|
| 1. מסך הגדרות AI — פירוט הוצאות ותקרה | ✅ מלא | הספק יסומן "מוגדר", ויופיעו סכומים אמיתיים (הערכה) |
| 2. בורר המודל + התג "נענה על-ידי" | ⚠️ חלקי | היום יש מודל אחד — **אי אפשר להחליף מודל ולהשוות**. עם מפתח יופיעו 2+ מודלים והתג ישתנה בין תשובות |
| 3. הודעת יציאת נתונים לבן משפחה | ⚠️ חלקי | היום ההודעה אומרת נכונה ש**כלום לא יוצא** (מודל דמה). עם מפתח היא תנקוב בשם החברה שמקבלת את הנתונים |

**התרגום הפשוט:** שלוש מתוך חמש היכולות שביקשת לראות ניתנות להדגמה מלאה היום. **השוואת מודלים** (הלב של "בורר המודל") ו**הסירוב בפועל של תקרת התקציב** דורשות מפתח — או את העקיפה שבסעיף 0.3.

### 0.2 כל סכום בשקלים במסכים האלה הוא הערכה, לא חיוב

מחירון הטוקנים שממנו מחושב כל ₪ במסך **לא אומת מול אף ספק**. מי שבנה את המחירון ניסה, ורשם בקוד למה זה נכשל (עמוד המחירים של Anthropic מפנה לתוכניות צרכניות, של OpenAI החזיר 403, ושל Google היה עמום לגבי המודל המסוים). המספרים שם הם מצייני-מקום מסומנים `UNVERIFIED`.

בנוסף, שער הדולר-שקל (3.75, נכון ל-17.8.2026) הוא מספר שנשמר ידנית.

**המשמעות המעשית:** אל תתייחס לתקרה החודשית כמגן על כסף אמיתי לפני שמישהו יבדוק את המחירים מול עמודי המחירים הרשמיים של שלושת הספקים. המסך אומר את זה בעצמו — תראה את זה בתרחיש 1.

### 0.3 אזהרת בטיחות — לפני שאתה שם מפתח כלשהו

בתרחיש 5 אני מבקש ממך לשים **מפתח דמה** (מחרוזת שאינה מפתח אמיתי) כדי לגרום למודל בתשלום להופיע בבורר. זה עובד כי בדיקת "האם הספק מוגדר" היא רק "האם משתנה הסביבה לא ריק".

**הכלל הקריטי, ואימתתי אותו בהרצה:**

- עם מפתח דמה **ותקרה של ₪0 או תקרה לא מוגדרת** — הבקשה נעצרת בשער העלויות **לפני** שנשלח משהו לספק. שום נתון לא עוזב את המחשב. זה מה שהופך את התרחיש לבטוח.

**לכן: אם שמת מפתח דמה, אל תגדיר תקרה גבוהה מ-0.** בסוף התרחיש מחק את הקובץ.

## 1. הפעלה ממחשב "קר"

### 1.1 דרישות מוקדמות (כבר מותקנות אצלך — אימתתי בהרצה)

- Node.js + npm
- Java (האמולטור של Firestore דורש אותו)
- התלויות של שתי החבילות. אם `functions/node_modules` חסר, הרץ פעם אחת:
  `cd ~/Documents/Family-Finance-App/functions && npm install && cd ..`

**אין צורך בשום מפתח או סיסמה חיצוניים** לכל התרחישים 1–4 ו-6. תרחיש 5 דורש רק את מחרוזת הדמה שאני נותן לך בגוף התרחיש.

### 1.2 טרמינל א' — האמולטורים

```bash
cd ~/Documents/Family-Finance-App
npm run emu
```

זה מריץ את `scripts/dev-emulators.ts`: בנייה ראשונית של `functions/`, ואז `tsc --watch` יחד עם `firebase emulators:start` (עם `--import`/`--export-on-exit` על `.emulator-data`, כך שהמשתמשים והנתונים שלך נשמרים בין הרצות).

**חכה לשורה:**

```
✔  All emulators ready! It is now safe to connect your app.
```

הרצתי את הפקודה הזאת ב-18.8 והיא עלתה נקי. הפורטים שהיא תדפיס:

| אמולטור | כתובת |
|---|---|
| Authentication | 127.0.0.1:9099 |
| Firestore | 127.0.0.1:8080 |
| Functions | 127.0.0.1:5001 |
| ממשק האמולטור | http://127.0.0.1:4400/ |

הערה שלא תפריע לך: firebase-tools מרים לבד גם אמולטור Hosting על פורט 5002 (וגם Logging על 4501). זה תקין ולא בשימוש בהדגמה — האפליקציה מוגשת מ-Vite.

### 1.3 טרמינל ב' — האפליקציה

```bash
cd ~/Documents/Family-Finance-App
npm run dev
```

אימתתי בהרצה: Vite עולה תוך פחות משנייה ומגיש 200 בכתובת **http://localhost:3000/**.

הקובץ `.env.local` כבר מכיל `VITE_USE_EMULATOR=1`, וזה מה שמחבר את האפליקציה לאמולטורים במקום לענן. אל תמחק אותו.

### 1.4 אם משהו לא עולה

- אם משתמש לא מצליח להתחבר, כנראה תיקיית `.emulator-data` נמחקה. שחזר עם:
  `npx tsx scripts/seed-members.ts --apply` ואז `npm run provision:auth`
  (שתי הפקודות דורשות שהאמולטורים כבר ירוצו).
- אם עריכה ב-`functions/src` לא משפיעה — היא כן משפיעה: `npm run emu` מריץ `tsc --watch` בדיוק בשביל זה. חפש בפלט `[tsc:watch] ... Found 0 errors`.

## 3. התרחישים

### תרחיש 1 — מסך הגדרות ה-AI (סופר-אדמין) · ~4 דקות

1. התחבר כ-**דויד**.
2. בתפריט הצד בחר **"הגדרות AI"**.

**מה אתה אמור לראות, מלמעלה למטה:**

1. **כותרת** "הגדרות AI".
2. **פס כתום** (הודעת יציאת הנתונים, דרישת §14.6 באפיון):
   > קריאות ה-AI (צ'אט וחילוץ מסמכים) נשלחות לספק המודל שנבחר ועוזבות את המחשב שלך — שאר הנתונים הפיננסיים נשארים מקומיים.
3. **שורת שער החליפין**: `שער דולר-שקל: 3.75 (נכון ל-2026-08-17)` ומתחתיה, בכתום:
   > מחירי המודלים לא אומתו מול הספקים — כל סכום בשקלים כאן הוא הערכה.

   זה סעיף 0.2 של המסמך הזה, כתוב על המסך עצמו.
4. **הסכום הכולל**: `סה״כ הוצאות AI החודש (כל הספקים): ₪0.00` ולידו כפתור ההסבר (סימן שאלה).
   מתחתיו, כי עדיין לא הגדרת תקרה:
   > טרם הוגדרה תקרה חודשית — קריאות AI בתשלום חסומות עד שתוגדר תקרה
5. **ארבע שורות ספקים** — מודל דמה / Anthropic / OpenAI / Google. אימתתי בהרצה שהשרת אכן מחזיר את כל הארבעה. **רק "מודל דמה" יסומן "מוגדר"**; שלושת האמיתיים יסומנו "לא מוגדר", כי אין מפתח.
6. **טבלת פירוט לפי מודל** — כרגע ריקה: "אין עדיין נתוני שימוש לפי מודל החודש". היא תתמלא בתרחיש 6.
7. **שדה התקרה** + כפתור "שמור תקרה".

**נסה את זה (30 שניות, ומראה שלושה מצבים שונים):**

| מה תקליד בשדה התקרה | מה אמור לקרות |
|---|---|
| `abc` | שגיאה מתחת לשדה — הערך נדחה, לא נשמר |
| `0` | ההודעה משתנה ל: "התקרה מוגדרת ל-₪0 — קריאות AI בתשלום חסומות" |
| `50` | מופיע פס התקדמות ו-"0% מהתקרה", והשורה העליונה הופכת ל-"₪0.00 מתוך ₪50.00" |

השלושה האלה הם שלושה מצבים שהקוד מבחין ביניהם בכוונה: "לא הוגדרה", "מוגדרת ל-0", ו"מוגדרת". ההבחנה הזאת הייתה תיקון של ממצא ביקורת — מצב שבו ערך פגום היה מוצג כ"לא הוגדרה תקרה" בדיוק ברגע שהוא ניטרל את השער לגמרי.

**לסיום התרחיש, השאר את התקרה על `50`** (זה בטוח — אין מפתח, אז אין קריאה בתשלום שיכולה לצאת).

> ⚠️ **הערה על מה שאתה קורא שם:** כפתור ההסבר של התקרה אומר "חריגה ממנו דורשת אישור מפורש של סופר-אדמין". מבחינת הקוד, מנגנון האישור **קיים בשרת אבל אין לו שום כפתור בממשק** — אין דרך, גם לא לך, לאשר חריגה מתוך האפליקציה. הבדיקה שלי: אין בכל קוד הלקוח שום קריאה ל-`requestAiOverageApproval`. בפועל, חריגה = חסימה, נקודה. פירוט בקובץ מדדי הקבלה שלצד המסמך הזה.

### תרחיש 2 — בורר המודל והתג ליד כל תשובה · ~2 דקות

1. עדיין כ-**דויד**, עבור ל-**"לוח תצוגה ראשי"**.
2. גלול לפאנל **"יועץ פיננסי אישי"** (הפאנל בגוון סגלגל).

**מה אתה רואה:**

- בראש הפאנל, ליד הכותרת: תיבת בחירה **"מודל"**, ולידה תגית כתומה **"מודל דמה"**.
- מתחת לתיבת הטקסט: שורה שקטה שאומרת שהמודל הנבחר הוא מודל דמה ושהשאלות לא נשלחות לספק חיצוני.

3. שאל שאלה בעברית, למשל: `כמה אני מוציא בחודש?`
4. התשובה תגיע, ומתחתיה תופיע שורה קטנה: **"נענה על-ידי מודל דמה (ללא מפתח)"**.

**מה שאתה לא יכול לראות היום, וזה חשוב:**

פתח את תיבת הבחירה. **יש בה אופציה אחת.** לכן אי אפשר לשאול את אותה שאלה פעמיים בשני מודלים ולהשוות — שזה בדיוק מה שהאפיון מבקש ("אפשר לשאול את אותה שאלה שוב במודל אחר ולהשוות").

מה שכן הוכח: התג מוצג **פר-תשובה** ונקרא מהשדה שהשרת החזיר לאותה הודעה, לא מהמצב הנוכחי של הבורר — כלומר כשיהיו שני מודלים, שתי תשובות באותה שיחה יישאו שני תגים שונים. את זה קראתי בקוד ומגובה בבדיקות אוטומטיות; **לא ראיתי את זה קורה על המסך**, כי אין מודל שני.

תוכן התשובה עצמו יגיד לך בעברית שאין מפתח מוגדר. זה מכוון.

### תרחיש 3 — הודעת יציאת הנתונים אצל מי שאינו סופר-אדמין · ~2 דקות

1. התנתק, והתחבר כ-**עומר** (`omer-levy@familyfinance.local`).
2. שים לב: **אין כרטיסיית "הגדרות AI" בתפריט.** אימתתי גם בצד השרת שהוא נחסם שם, לא רק שהכרטיסייה מוסתרת.
3. עבור ל-"לוח תצוגה ראשי" ← פאנל הצ'אט.
4. **מתחת לתיבת הטקסט, מעל כפתור השליחה**, יש שורה קבועה (לא באנר שנסגר):
   > המודל הנבחר הוא מודל דמה — השאלות שלך לא נשלחות לספק AI חיצוני.
5. חזור על אותו הדבר כ-**לילית**. אותה שורה, אותו מקום.
6. עבור לכרטיסייה **"תיקייה חודשית"** ← לחץ להעלאת מסמכים. גם שם, מתחת לבורר המודל:
   > המודל הנבחר הוא מודל דמה — המסמך לא נשלח לספק AI חיצוני.

**מה שאתה לא יכול לראות היום:** ההודעה בנוסח שלה שחשוב באמת — זה שנוקב בשם החברה. עם מפתח, אותה שורה תקרא *"השאלות שלך נשלחות ל-Anthropic ועוזבות את המחשב שלך"*, והשם ישתנה כשתחליף מודל בבורר.

הבחירה לתת למודל הדמה נוסח משלו הייתה מכוונת: לומר למשפחה שהשאלה "נשלחה למודל דמה" היה משפט **שקרי**, כי המודל הזה רץ בתוך הפונקציה שלנו ולא יוצא לשום מקום.

### תרחיש 4 — חילוץ מסמך ושער האישור האנושי · ~4 דקות

זה התיקון הכי משמעותי בשלב הזה. לפניו, המערכת כתבה תנועות שה-AI חילץ **ישירות לספר החשבונות של המשפחה, בלי שאף אחד אישר אותן**.

1. אפשר להישאר כ-**עומר** (הכרטיסייה פתוחה לכל התפקידים) או לחזור ל-**דויד**.
2. כרטיסייה **"תיקייה חודשית"** ← לחץ על אזור ההעלאה.

**עכשיו הנקודה של התרחיש:** **שום דבר עדיין לא נשמר.** נפתח חלון **"בדיקת נתונים שחולצו"**:

2. **הורד את הסימון** מהשורה — היא מתעמעמת והשדות ננעלים.

### תרחיש 5 — הסירוב כשחורגים מהתקרה · ~3 דקות · **דורש את העקיפה שבסעיף 0.3**

בלי מודל בתשלום, אי אפשר לראות את זה: קריאה למודל דמה **פטורה מהתקרה לחלוטין, בכל מצב שלה**. אימתתי — קריאה למודל דמה עברה בהצלחה גם כשהתקרה הייתה ₪0.

**קרא שוב את סעיף 0.3 לפני הצעד הראשון.**

1. **עצור את האמולטורים** (Ctrl+C בטרמינל א').
2. צור קובץ בשם `functions/.env.local` עם השורה הזאת בלבד:

   ```
   ANTHROPIC_API_KEY=placeholder-not-a-real-key
   ```

3. הרץ שוב `npm run emu` וחכה ל-"All emulators ready".
4. התחבר כ-**דויד** ← **"הגדרות AI"**.
   שורת Anthropic הפכה ל-**"מוגדר"**. אימתתי בהרצה שהשרת מחזיר עכשיו שני מודלים לצ'אט — מודל דמה **ו-Claude Sonnet 5** — ואלה בדיוק המודלים שהבורר מציג.
5. **הגדר את התקרה ל-`0` ושמור.** אל תדלג על זה — זה מה שמונע מהבקשה לצאת החוצה.
6. עבור ללוח התצוגה ← בבורר המודל בחר **Claude Sonnet 5** ← שאל שאלה כלשהי.

**מה אתה אמור לראות** (זה הפלט המדויק שקיבלתי מהשרת בהרצה חיה):

> חריגה מתקרת ה-AI החודשית — נדרש אישור מפורש של סופר-אדמין

התשובה מעולם לא נשלחה לספק. השער עצר אותה קודם.

7. **בונוס — נסה למחוק את התקרה ולשמור שדה ריק.** הוא לא נשמר כ-0 בשקט; תקבל:
   > יש להזין תקרה חודשית — כדי לחסום קריאות AI בתשלום יש להזין 0 במפורש

   זה בעצמו היה ממצא ביקורת: קודם שדה ריק נשמר כ-0, ואז נקרא כ"לא הוגדרה תקרה" — כך שכל קריאה בתשלום נכשלה בהודעה "התקרה טרם הוגדרה", מוצגת לאדם שזה עתה הגדיר אותה. יש גם הודעת סירוב שלישית, נפרדת, למקרה שהערך השמור פגום. שלוש ההודעות שונות במכוון, כי הפעולה הנדרשת שונה בכל אחת.

8. **ניקוי — אל תדלג:**
   ```bash
   rm ~/Documents/Family-Finance-App/functions/.env.local
   ```
   ואז הפעל מחדש את האמולטורים.

**מה שהתרחיש הזה לא מראה:** את הצד השני של הסיפור — קריאה שמצליחה, מנכה מהתקציב, ומופיעה בפירוט עם סכום אמיתי. לזה צריך מפתח אמיתי (נספח א').

2. הפעל מחדש את האמולטורים.

4. אז ורק אז: תרחיש 2 הופך להשוואת מודלים אמיתית, תרחיש 3 נוקב בשם החברה, ותרחיש 6 מציג כסף.

> **ממצא שכדאי שתדע עליו מראש, מצאתי אותו בהרצה:** אם המפתח שגוי, פג-תוקף, או שנפלה בו טעות הקלדה — ההודעה שתקבל בעברית היא ההודעה הכללית ביותר שיש: *"קריאה ל-AI נכשלה מסיבה לא צפויה — נסה שוב, ואם זה חוזר על עצמו פנה לתמיכה."* היא לא רומזת שהבעיה היא המפתח. הרצתי את זה: הספק החזיר שגיאת אימות 401, והמסווג בקוד לא מכיר קטגוריה כזאת. זה לא חוסם את ההדגמה, אבל זה כנראה תהיה התקלה הראשונה שתפגוש ביום שתחבר מפתח, וההודעה תשלח אותך לכיוון הלא נכון. רשמתי את זה כממצא לתיקון.
